# WayAble QA 테스트 시나리오 및 테스트 케이스

## 0. 문서 개요

- **목적**: 검색, 조회, 저장, 수정, 회원 탈퇴 등 핵심 기능 흐름에 대해 QA 진행 전 시나리오와 테스트 케이스를 정리한다.
- **작성 기준**: 현재 `dev` 브랜치 코드(화면/로직) 분석을 바탕으로 작성. 실제 동작과 문서 내용이 다를 경우 코드가 최신 기준이며, 이 문서는 QA 진행 중 업데이트가 필요하다.
- **테스트 환경 제안**: 실기기(Note9 기준) + `Pixel_7_API31`(1080x2220@420dpi), `Galaxy_S_360dp_API31`(1080x2340@480dpi, 좁은 화면 QA용) 두 AVD 병행. TalkBack(Android 스크린리더) ON/OFF 각각 1회 이상 점검 권장.
- **우선순위 기준**
  - **P0**: 핵심 플로우, 실패 시 서비스 이용 불가 수준 (예: 로그인, 탈퇴, 저장/해제)
  - **P1**: 주요 기능이나 우회 가능하거나 영향 범위가 제한적
  - **P2**: 부가 기능, UX 디테일, 엣지 케이스
- **결과 컬럼 사용법**: QA 진행 시 `결과` 컬럼에 Pass / Fail / Blocked 기입, `비고`에 재현 조건·스크린샷 링크·이슈 번호 기재.
- **범위 밖**: 결제, 리뷰/평점 작성(현재 앱에 리뷰 기능 없음), 알림 설정(현재 없음), 닉네임/프로필 사진 수정(현재 없음) — 코드 확인 결과 미구현 기능으로, 필요 시 별도 확인 요망.

### 9-1-1. 수정 내역 및 재검증 결과

- **BUG-01 수정**: `auth_provider.dart`에 `AuthStateNotifier.restoreSession()` 추가(앱 시작 시 `FirebaseAuth.instance.currentUser`를 확인하고 존재하면 Firestore에서 유저 정보를 읽어와 상태에 반영). `landing.dart`가 스플래시 애니메이션과 동시에 이 복원을 실행하고, 완료되면 로그인 여부에 따라 `MainShell`/`LoginScreen` 중 하나로 라우팅하도록 변경. 실기기에서 앱을 완전히 재시작해도 재로그인 없이 바로 홈 화면으로 진입하는 것 확인.
- **BUG-02 수정**: 논의 끝에 "대분류·편의정보 모두 기존 값으로 미리 채우되, 저장 이력이 없는 대분류(이번에 새로 추가한 대분류)는 자연히 빈 상태로 시작"하는 방향으로 확정. `accessibility_screen.dart`(1단계)와 `accessibility_detail_screen.dart`(2단계) 각각의 `initState`에서 현재 로그인한 유저의 `accessibilityFieldsByProfile`을 읽어 대분류/전체·개별 편의정보 선택 상태를 복원하도록 구현. 별도의 케이스 분기 없이 "대분류별로 저장 이력이 있으면 복원, 없으면 빈 상태" 규칙 하나로 다음 두 시나리오가 모두 자연스럽게 처리됨을 실기기에서 확인:
  - 기존 대분류 해제 + 신규 대분류 선택 → 신규 대분류는 편의정보도 빈 상태
  - 기존 대분류 유지 + 신규 대분류 추가 → 기존 대분류는 편의정보 복원, 신규 대분류는 빈 상태
- **실기기 재검증**: 지체장애 보조("주차 여부"·"접근로"), 영유아 가족("유아용 보조의자"), 고령자 동반("엘리베이터"·"화장실") 모두 저장돼 있던 개별 항목 그대로 정상 복원됨을 확인. (최초 검증 때 고령자 동반 섹션 스크린샷을 화면 아래까지 내려보지 않고 판단해 "선택된 게 없다"고 잘못 기록했던 것으로, 실제로는 해당 항목이 화면 하단에 더 있었을 뿐 복원 로직 자체엔 결함이 없었음 — 재확인 후 정정)

- **수정**: 해당 호출을 try/catch로 감싸 예외 발생 시 `null`로 처리(캐시된 마지막 위치 없음과 동일하게 취급)하도록 변경
- **재검증**: 위치 권한 거부 상태로 지도 탭 진입 → 로딩 오버레이가 정상적으로 걷히고 서울시청 기본 위치로 표시됨. 지도를 손으로 이동해 "이 장소 재검색" 실행, 카테고리 필터 탭으로 검색 실행 → 결과 목록(거리·적합성 레벨·이미지 포함)까지 정상 로드되는 것 확인. 크래시 없음

**[수정 완료] BUG-06. 상세 페이지에서 외부 홈페이지 링크로 나갔다가 돌아오면 지도 화면이 고착되어 하단 탭 전환이 안 됨**

- **결과**: 화면에는 지도 탭 콘텐츠가 (실제로는 비활성 탭인데도) 그대로 떠 있고, 하단 탭 바는 이전에 보고 있던 탭(예: 맞춤 여행지 탐색)이 선택된 상태로 표시됨. 홈/저장목록/마이페이지/탐색 등 어떤 하단 탭을 눌러도 화면이 전환되지 않다가, 지도 탭을 한 번 눌러야(그 순간 지도가 초기 위치로 다시 그려짐) 비로소 이후 탭 전환이 정상적으로 작동함
- **원인**: [`lib/screen/search/map_screen.dart`](../lib/screen/search/map_screen.dart)의 카카오맵은 하이브리드 컴포지션(`forceHybridComposition: true`, 네이티브 SurfaceView) 기반 플랫폼 뷰라 안드로이드 뷰 계층에 Flutter의 `Offstage`와 별도로 붙어있음. 앱이 백그라운드로 갔다가(외부 브라우저 실행 등) 복귀하면 안드로이드가 화면 복귀 시 하드웨어 레이어 순서를 안드로이드 뷰 계층 기준으로만 다시 잡는데, 이 과정이 그 시점 Flutter의 `Offstage` 상태(지도 탭이 비활성이라 숨겨져 있어야 함)를 반영하지 못해 SurfaceView가 다른 화면 위에 계속 떠 있는 상태로 남는 경우가 있었음
- **수정**: `_MapScreenState`에 `WidgetsBindingObserver`를 추가해 앱이 `resumed` 상태로 돌아오는 시점을 감지하고, 그때 지도 탭이 비활성 상태(`!widget.isActive`)라면 `KakaoMap`의 `key`를 새로 발급해 플랫폼 뷰를 강제로 떼었다 다시 붙임(카메라 위치는 리셋하지 않고 마지막 위치(`_currentPosition`)로 다시 그리도록 `option`도 함께 수정). 지도 탭이 실제로 활성 상태일 때는 이 로직이 동작하지 않아 평소 지도 사용에는 영향 없음
- **재검증**: 실기기에서 탐색 탭 검색 결과 상세 페이지 → 홈페이지 링크 → 외부 브라우저 → (a) 뒤로가기로 복귀, (b) 홈 버튼 후 최근 앱 목록에서 복귀, 두 경로 모두 테스트. 두 경로 모두 상세 페이지가 정상적으로 다시 보이고, 곧이어 하단 탭(홈/지도)을 눌렀을 때 화면이 즉시 정상 전환됨을 확인. 지도 탭으로 전환 시 이전 카메라 위치(마지막으로 보고 있던 지역)가 그대로 유지되는 것도 확인(불필요한 리셋 없음)

**[수정 완료] BUG-07. "접근성 유형별 여행지 찾기" 카드를 두 번째부터 누르면 카드의 대분류가 아니라 내 저장된 접근성 프로필로 검색됨**

- **재현**: 홈 화면에서 "접근성 유형별 여행지 찾기" 카드(예: 지체장애 보조)를 눌러 정상 동작 확인 → 결과 확인 후 다른 탭(홈 등)으로 이동 → 다시 홈 화면에서 다른 카드(예: 청각장애 보조)를 누름
- **결과**: 눌렀던 카드의 대분류만 켜고 지역·카테고리를 전부 초기화해서 검색해야 하는데, 실제로는 로그인 계정에 저장된 접근성 프로필(대분류+편의정보)이 그대로 적용된 상태로 검색됨 — 카드를 눌러도 눌렀던 대분류로 바뀌지 않음
- **원인**: 홈 화면의 카드 탭 핸들러가 `pendingAccessibilityRequestProvider`(요청한 대분류)와 `tabSwitchRequestProvider`(탐색 탭으로 전환)를 동시에 갱신하는데, [`lib/screen/search/explore_screen.dart`](../lib/screen/search/explore_screen.dart)는 탐색 탭을 한 번 방문하면 `Offstage`로 계속 살아있어 `initState`가 다시 돌지 않음(MainShell의 탭 유지 방식). 두 번째부터는 이미 살아있는 화면의 `ref.listen`이 pending 요청을 먼저 정확히 적용하지만, 곧이어 탭 전환으로 인한 리빌드에서 `didUpdateWidget`의 "탭이 활성화되면 저장된 기본값으로 리셋" 로직이 뒤늦게 실행되면서 방금 적용한 카드의 대분류 필터를 사용자의 저장된 프로필로 덮어써 버림
- **수정**: `_ExploreScreenState`에 `_skipNextActivationReset` 플래그를 추가. 카드 요청을 처리하는 `ref.listen` 콜백이 이 플래그를 true로 세팅해두면, 바로 뒤이어 실행되는 `didUpdateWidget`의 활성화 리셋이 이번 한 번만 건너뛰도록 함(일반적인 탭 전환 시의 리셋 동작에는 영향 없음)
- **재검증**: 실기기에서 지체장애 보조 카드 → 결과 확인(8735건, 지체장애만 활성) → 홈 탭 이동 → 청각장애 보조 카드 재실행 → 지체장애는 꺼지고 청각장애만 켜진 채로 지역/카테고리 초기화된 상태로 재검색(98건)되는 것 확인

**[수정 완료] BUG-08. 지도 검색 결과 카드에서 편의정보 칩이 없는 여행지는 주소~이미지 사이 여백이 비정상적으로 넓어 보임**

- **재현**: 지도 탭에서 현위치 주변 카테고리 검색 → 지도를 손으로 이동 → 카테고리를 쇼핑으로 바꿔 재검색 → 결과 목록에서 이마트/홈플러스처럼 편의정보 칩이 하나도 없는 여행지 카드를 확인
- **결과**: 편의칩이 있는 카드(예: 현대프리미엄아울렛 SPACE1)는 정상인데, 칩이 없는 카드(이마트 진접점, 이마트 다산점, 홈플러스 진접점 등)는 주소 줄과 이미지 사이에 주소 두 줄이 더 들어갈 만큼 큰 빈 공간이 생김
- **원인**: [`lib/screen/search/map_screen.dart`](../lib/screen/search/map_screen.dart)의 `_SpotListCard`가 편의칩 줄 영역을 "칩이 있든 없든 카드 높이가 흔들리지 않도록" 항상 고정 높이로 그리고 있었음(칩이 0개여도 빈 줄 자리를 그대로 예약). 이미지가 없는 여행지는 그 영역 자체를 아예 안 그리는 것과 달리, 칩 없는 여행지는 빈 영역만 남아 눈에 띄게 벌어져 보였음
- **수정**: 이미지 영역과 동일한 패턴으로, 편의칩이 하나도 없으면(`facilityLabels.isEmpty`) 그 줄(간격 포함)을 통째로 생략하도록 변경. 칩이 없을 때는 이미지가 주소 바로 아래로 붙어서 나옴(둘 다 없으면 아무 간격도 없이 카드가 끝남). 카드 높이 예산(`_cardExtentFor`, 리스트 스크롤 위치 계산에 쓰임)도 실제로 그려지는 조각만 반영하도록 함께 재계산하도록 수정
- **재검증**: 실기기에서 동일 조건(현위치 검색 → 지도 이동 → 쇼핑 카테고리 재검색)으로 재현 → 칩 없는 여행지(구리갈매 지역 매장 등) 카드가 주소 바로 아래 이미지가 붙어서 나오는 것 확인, 칩 있는 카드는 기존과 동일하게 정상 표시됨

### 9-2. 화면 이상 / UX 개선 여지 (P2)

**ISSUE-01. 지도 검색의 "레벨 산정 중" 배지가 게스트/미설정 사용자에게 계속 로딩 중처럼 보임**

- 게스트 또는 접근성 프로필 미설정 상태로 지도 검색을 하면 모든 결과 카드에 "레벨 산정 중" 배지가 뜨는데, 이 상태는 실제로는 "계산 불가"를 뜻하는 고정 라벨이며([`lib/utils/accessibility_fit_level.dart`](../lib/utils/accessibility_fit_level.dart) L45-48 주석에 의도가 명시됨) 절대 "산정 완료"로 바뀌지 않음
- 문구가 진행 중(loading) 상태처럼 읽혀서, 실제로는 "프로필을 설정해야 계산되는 값"이라는 걸 사용자가 오해하기 쉬움 — 정보 아이콘(ⓘ) 툴팁을 눌러야만 진짜 의미를 알 수 있음
- 제안: 게스트/미설정 상태에서는 문구를 "프로필 설정 필요" 등으로 구분하거나, 배지 자체를 숨기는 편이 명확함

**ISSUE-02. 상하단 이동 FAB가 검색 결과 카드와 겹치거나 빈 상태에서도 노출됨**

- 검색 결과가 한 페이지 안에 다 들어올 때, 화면 우하단에 고정된 상/하단 이동 버튼이 마지막 줄 카드(제목/주소 텍스트)와 겹쳐 보임(예: 탐색 화면 "윤이상 기념공원" 카드, 지도 화면 하단시트 리스트)
- "검색 결과가 없습니다" 같은 스크롤할 내용이 전혀 없는 빈 상태에서도 이 버튼들이 계속 떠 있음(눌러도 아무 효과 없음)
- 제안: 리스트 길이가 한 화면을 넘지 않을 때, 혹은 결과가 0건일 때는 버튼을 숨기는 조건 추가

### 9-3. 확인된 정상 동작 (참고)

이번 실행에서 별도 이슈 없이 기대대로 동작한 주요 항목: 게스트 로그인 유도 다이얼로그(SAVE-01, VIEW-11), 탐색 화면 지역/카테고리 필터 및 페이지네이션(SEARCH-E01~E13), 지도 화면 카테고리 검색·재검색·스크린리더 안내(SEARCH-M01~M06), 상세화면 이미지·시설정보(VIEW-01), 폴더 생성/이름 10자 제한/최대 10개 제한/삭제 확인 다이얼로그(SAVE-03~05, SAVE-11~12), 회원탈퇴 확인/취소 다이얼로그 문구(DEL-01~02). 또한 이전에 수정한 "폴더 편집 중 뒤로가기 시 앱이 꺼지는 문제"와 "순서 편집 중 뒤로가기는 순서 편집만 종료 → 한 번 더 누르면 저장 목록으로" 동작도 실기기에서 정상 확인됨.
